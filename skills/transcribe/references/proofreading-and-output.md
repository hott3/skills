# 誤字補正ワークフロー & 出力先別フォーマット

文字起こしテキストの品質を仕上げ、ユーザーが指定した出力先（Markdown / Cosense等）へ安全に反映するためのルール。

---

## 1. 誤字補正（対応表レビュー）の進め方

自動生成字幕やASRの出力には、同音異義語・固有名詞・専門用語・数字の誤変換が含まれる。以下の原則で補正する。

1. **勝手に全面修正して上書きしない**:
   特に複数の動画・長文を扱う場合、まず **1本分（または1セクション分）で対応表を提示** し、表記ゆれの方針（「アール・ヌーボー」か「アール・ヌーヴォー」か、中黒の有無など）をユーザーと合わせる。方針が固まれば、残りを一括で対応表化・反映できる。
2. **対応表の必須フォーマット**:
   ```markdown
   | タイムスタンプ | 現在の表記（自動字幕/ASR） | 修正後の表記 | 根拠（映像テロップ・文脈） |
   | :--- | :--- | :--- | :--- |
   | `(01:00)` | `レシート呼ばれる人たちは` | `弟子と呼ばれる人たちは` | 01:15スライド・テロップ「弟子と呼ばれる人たちは」 |
   ```
3. **話者名の確定（話者分離を行った場合）**:
   初回出力時は `(SPEAKER_00)` / `(SPEAKER_01)` の仮ラベルを付与し、対応表レビュー時に実際の話者名を確認して一括置換する。
   ```markdown
   | 仮ラベル | 確定後の話者名 | 根拠（発話内容・役割等） |
   | :--- | :--- | :--- |
   | `SPEAKER_00` | `話者A` | 00:05 冒頭の説明・進行役 |
   | `SPEAKER_01` | `話者B` | 00:21 質問・応答 |
   ```
4. **ノイズ除去**:
   意味のない単発の相槌（「ん」「んだった」等）は削除対象として対応表に明記する。
5. **追加オプションの確認（テンプレート）**:
   「事前の Web 検索による固有名詞補完」と「本題に関係ない会話のカット」は強制の標準ステップにせず**オプション扱い**とし、対応表の下に以下の確認欄を添えてユーザーに判断・発見を促す。
   ```markdown
   ### 追加オプションの確認
   - 特定の業界・製品に関する固有名詞について、Web検索による用語補完や再変換を行いますか？
   - 雑談・移動中の道案内など、本題に関係ない会話パートのカットリストを提示しましょうか？
   ```
6. **ASR エンジン・モデル再実行時の再レビュー必須化**:
   別の ASR エンジンやモデル（例：`faster-whisper` → `WhisperX`、または `small` → `large-v3`）で文字起こしをやり直した場合、出力テキスト・誤変換箇所・タイムスタンプが変化する。前回の置換辞書をそのまま機械的に流用して出力先へ反映せず、**必ず新しい出力に対して再度対応表レビューを実施し、ユーザーの承認を得てから反映する**。

## 2. 出力先別フォーマット

### A. Markdownアーティファクトとして出力する場合
- 長文や複数本の文字起こしは、チャット本文に直接貼らず Markdown アーティファクト（例: `transcripts.md`）に書き出す。
- 冒頭に「目次（動画/音声一覧＋再生時間）」と「注記（自動生成字幕・ASRベースであること）」を置く。
- タイムスタンプは `**[MM:SS]**` 形式で60秒ごと（または話の区切りごと）に配置する。

### B. Cosense（Scrapbox）へ書き込む場合
Cosenseへの書き込み自体は `cosense` スキルおよび `cosense-write-style` スキルの手順に完全に従う。文字起こしデータの整形では以下の4点を徹底する。

1. **コードブロック（`code:`）の活用**:
   文字起こし本文は通常の段落ではなく、`code:<連番_タイトル>.txt` のコードブロック内に格納する。これにより、長い文字起こし本文が折りたたみ・コピーしやすくなり、本文中の記号が意図せずリンク化されるのも防げる。
   各回の見出し・`参照`・`code:`・`感想・関連リンク`・完了メッセージはルート階層（インデント0）に置き、それぞれの配下要素だけをタブ1段下げる。複数回を並べる場合はセクション間に2〜3行の空行を入れて区切る。
   ```text
   [* 01. タイトル (6:51)]
   参照
   	https://www.youtube.com/watch?v=...
   code:01_タイトル.txt
   	(00:01) 本文...
   	(01:00) 本文...
   感想・関連リンク [ユーザー.icon]
   	[関連ページ1]
   
   「タイトル」の文字起こし、完了です[author:モッフィー.icon]
   ```

   **話者分離ありの出力フォーマット（`code:` ブロック内）**:
   Cosense のリンク記法 `[xxx]` との衝突を防ぐため、話者ラベルは **`(話者名)`** 形式を使用する。標準は「話者切り替わりブロック形式」、掛け合いが細かい会話では「1行ごとラベル形式」を選択する。

   - **標準案：話者切り替わりブロック形式**
     ```text
     code:01_sample_meeting.txt
     	=== 01. サンプル会議タイトル ===
     	(話者A)
     	(00:11) 話者Aの発言サンプル1行目です。
     	(00:14) 話者Aの発言サンプル2行目です。
     	
     	(話者B)
     	(00:21) 話者Bの応答サンプルテキストです。
     	
     	(話者A)
     	(00:30) 話者Aの補足発言サンプルテキストです。
     ```

   - **代替案：1行ごとラベル形式（掛け合いが細かい会話向け）**
     ```text
     code:01_sample_meeting.txt
     	=== 01. サンプル会議タイトル ===
     	(00:11) (話者A) 話者Aの発言サンプル1行目です。
     	(00:14) (話者A) 話者Aの発言サンプル2行目です。
     	(00:21) (話者B) 話者Bの応答サンプルテキストです。
     	(00:30) (話者A) 話者Aの補足発言サンプルテキストです。
     ```

2. **構文衝突・意図しないリンク化の無害化**:
   - タイムスタンプは `[00:01]` ではなく **`(00:01)`** を使う。
   - 話者ラベルは `[話者A]` ではなく **`(話者A)`** を使う。
   - `[音楽]` `[笑い]` `[拍手]` 等の環境音タグは **`(音楽)` `(笑い)`** に変換する。
   - コードブロック外で `#タグ` として意図しない単語がリンク化されないよう、`#` の直後に文字が続く箇所はバッククォートで囲む。
   - `[author:モッフィー.icon]` 等の署名アイコンは `code:` ブロックの **外側**（同じ親インデント階層）に置く。
3. **関連先内部リンクの整理**:
   - 文字起こしから抽出したキーワードを「感想・関連リンク」欄に箇条書きで提案する際は、まず `cosense listPages` / `searchFullText` で **プロジェクト内にすでに存在するページ** と **新規リンク候補** を区別して提示する。
4. **大規模ページのバッチ分割反映**:
   - Cosenseの `previewEdit` API にはリクエストサイズ上限（約100KB / 超過時 `HTTP 413 Request Entity Too Large` / `Payload Too Large`）がある。約57KB（約1,100行）規模でも超過するケースがあるため、安全マージンを取って分割する。
   - 複数本をまとめて書き込む・更新する場合は、1リクエストあたり **15〜20KB程度（約300〜350行単位）** に分割し、同じアンカー行への `insertBefore` や `replace` で順次 `previewEdit` → `submitEdit` を実行する。
