# Transcribe Skill（文字起こし標準ワークフロー）

あらゆるメディアソースの文字起こしを、**「抽出（字幕優先） → 整形 → 誤字検証（対応表レビュー） → 出力先最適化」** の4ステップで一貫して行う。

## 共通4ステップワークフロー

### Step 1: ソース取得・文字起こし抽出
1. **既存字幕の確認（YouTube等の場合）**: 最初から重い音声認識（ASR）にかけず、まず `yt-dlp` 等で既存の字幕・自動生成字幕と元言語のタイトルが取得できるか確認する。
2. **音声抽出・ASR（字幕がない場合 / ボイスメモ / ローカルファイル / 音楽）**: `ffmpeg` で16kHzモノラルWAVへ変換し、環境に応じたASRエンジン（`faster-whisper` / `openai-whisper` 等）でテキスト化する。

### Step 2: クリーニング・整形
- ロール表示の重複行・タイムスタンプタグ（`<c>` 等）・HTMLエンティティを除去する。
- `[音楽]` `[笑い]` 等の環境音タグや、出力先の構文と衝突する記号（Cosenseの `[]` や `#` など）を事前に処理する。
- 読みやすさのため、一定間隔（標準60秒）ごとのタイムスタンプ見出しを付与して段落化する。

### Step 3: 誤字検証と対応表レビュー（重要）
音声認識（自動生成字幕・ASR）には固有名詞や専門用語の誤変換が必ず含まれる。**推測で勝手に書き換えず、以下の手順でユーザーと合意しながら精度を高める。**

1. **根拠の確認**:
   - 動画ソースがある場合は、誤字が疑われるタイムスタンプの静止画フレームを `ffmpeg` で切り出し（`tile=3x3` 等のコンタクトシート推奨）、画面内テロップ・スライドの文字を目視確認する。
   - 音声のみの場合は、前後の文脈や専門用語の一般的な表記から候補を特定する。
2. **対応表の提示**: `タイムスタンプ | 現在の表記 | 修正後の表記 | 根拠` の形式で対応表を作成し、ユーザーに確認を求める。
3. **承認後の反映**: ユーザーの承認を得てからテキスト・出力先に一括反映する。

### Step 4: 出力・連携
- 出力先（チャット直接回答、Markdownアーティファクト、Cosenseページ等）のルールに従って整形・保存する。
- Cosense（Scrapbox）へ書き込む場合は、`code:` ブロックの活用・構文衝突の無害化・`cosense` / `cosense-write-style` スキルの作法（署名アイコン・声かけ・バッチ分割）に従う。詳細は [references/proofreading-and-output.md](references/proofreading-and-output.md) を参照。
